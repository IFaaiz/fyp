## Per-corpus evidence and integration guidance

### Airspace / RADAR conference-planning corpus

The CMU Airspace source page lists a v1.0 wargaming archive and describes the 711-message release, its largely fabricated content, and its no-redistribution instruction. The syntax guide documents the `X-RADAR Label`, `Noise`, and `Replyto` fields. The integration agent parsed 711 `.eml` records with 711 unique source IDs. Of these, 580 have labels, 131 have no label, and 28 have two labels (608 label instances total). The released source labels are `BRIEFING` 101, `CHANGE-ROOM` 112, `CHANGE-SESSION` 74, `CHANGE-SPEAKER` 63, `INFO-REQ` 63, `MISC-ACTION` 63, `WEB-VIO` 96, and `WEB-WBE` 36. `Noise` is false for 662 and true for 49. Every `X-RADAR-Replyto` is `0`, so the current archive shows no reply edges. The downloaded ZIP is 1,063,031 bytes, SHA-256 `04f8c82dc96ca00d565b5598e73424e35dbac4692ffa4d98271fe0c54bcc31a7`, and passed its archive CRC check. The raw `X-RADAR-Thread` field has 82 values (448 messages use `0`); these are unverified simulator groups, not reply links. Preserve local-only storage at `ai/data/raw/airspace/`. [CMU Airspace page](https://www.cs.cmu.edu/~airspace/) · [Syntax and usage PDF](https://www.cs.cmu.edu/~airspace/corpus/README_EmailSyntax_1.0.pdf) · [Official ZIP](https://www.cs.cmu.edu/~airspace/corpus/Airspace_wargaming_1.0.zip)

Retain all eight source label values, including `WEB-VIO` and `WEB-WBE`, and keep `Noise` and the empty/zero reply field as their own fields. These categories provide auxiliary change/request/scope supervision; they are not equivalent to FYP labels. Do not map `INFO-REQ → REPORT_REQUEST` or `MISC-ACTION → ACTION_REQUEST` without separately reviewed evidence.

### RADAR Action-Item dataset

The official CMU page offers `action-item-dataset.tgz`, states that an IRB panel review determined the anonymized data could be distributed for research, and describes random same-length token substitution. The integration agent’s archive audit matched 744 messages, 744 judgments, mappings and annotation files; 328 judgments are positive and 416 negative. It verified 416 action-item spans and 20,815 additional annotation records across 30 source types. The full source-slice validation is reported by the integration workstream. The archive SHA-256 is recorded above. The page does not name an open license, so do not label it Apache/CC or infer broad redistribution from the research-distribution statement. [Official CMU page](https://www.cs.cmu.edu/~pbennett/action-item-dataset.html) · [Official archive](http://www.cs.cmu.edu/~pbennett/action-item-dataset.tgz)

Keep the release’s action-present judgment and action-item character spans as its own supervision. The anonymization breaks ordinary lexical transfer, so evaluate transfer on the de-anonymized structure only if the authorized source itself provides it; do not reverse token substitutions. Never relabel every action-item positive as FYP `ACTION_REQUEST`.

### Parakweet Email Intent Data Set

The original ParakweetLabs repository says the data are sentence-level email intent data and declares Apache License 2.0 in both the README and `LICENSE`. Its wiki says examples come from Enron and defines “intent” primarily as request/propose, with some commit examples included when they contain a date/time. The preserved release labels are the binary `Yes` / `No` values; it does not expose a single exhaustive fine-grained speech-act label per example. [Repository](https://github.com/ParakweetLabs/EmailIntentDataSet) · [README](https://raw.githubusercontent.com/ParakweetLabs/EmailIntentDataSet/master/README.md) · [LICENSE](https://raw.githubusercontent.com/ParakweetLabs/EmailIntentDataSet/master/LICENSE) · [Author task definition and cited counts](https://github.com/ParakweetLabs/EmailIntentDataSet/wiki)

Use it only as binary intent auxiliary supervision. Treat `Yes` as an intent/response signal, not a direct FYP label. Register `origin_corpus=Enron`, `overlap_family=ENRON`; global message fingerprints and source membership checks are mandatory because the same underlying Enron messages may appear in MailEx or a later FYP split.

The pinned commit `055f62857b3214c1682a0b18a2c5fc2c9f0c00e6` has now been acquired and independently checked against all 4,649 parsed records: TRAIN 3,657 (1,719 Yes / 1,938 No), TEST 992 (309 Yes / 683 No). Four exact sentence texts cross the source splits. The wiki counts remain separately recorded. File checksums are in `parakweet_registry_proposal.json` and the canonical registry. Original email identities are missing, so all rows remain quarantined from training against the new Enron evaluation. The user approved brief private excerpts, and the orchestrator inspected 50 examples on 2026-10-03. Binary source labels are preserved; no FYP mapping is inferred.

### CEREC

The author repo provides a 16.2 MB ZIP in `data/COLING/`; the paper describes tokenized email threads in CoNLL-like format with mention/coreference annotations. It is explicitly Enron-derived. Preserve the original entity inventory (`PERSON`, `ORGANIZATION`, `LOCATION`, `DIGITAL`) and the authors’ mention/coreference structure. [Author repository](https://github.com/paragdakle/emailcoref) · [Archive page](https://github.com/paragdakle/emailcoref/blob/master/data/COLING/cerec.zip) · [COLING paper](https://aclanthology.org/2020.coling-main.30.pdf)

The repository carries an Apache-2.0 license marker, and the COLING paper states CC BY 4.0. Since the released CoNLL corpus includes Enron-derived message tokens and the author materials do not clearly state how those grants apply to the embedded source emails, record the message-bearing corpus as license-scope unresolved and do not redistribute its text. This is not a claim that the author annotations have no license; it is a boundary on what the currently visible licensing evidence establishes. Record `origin_corpus=Enron`, `overlap_family=ENRON` and apply the same global leakage control as MailEx and Parakweet.

The pinned commit `d86bdcdf963b4181aa7d6a3e3ca761c971ab27d9` has now been acquired for private inspection. The ZIP SHA-256 is `6719223815d6a2301c01a596892d76c0cf33a03fff0ac53f7b43de4b93bc830b`. The orchestrator reran its aggregate parser: the main file contains 6,001 documents, 6,567,125 token rows and 60,383 distinct per-document numeric coreference IDs. That matches the updated author paper; the 38,996 count in the original paper/repository remains recorded separately. All five source files have seven double-tab columns, despite one README reference to eight. Message feature counts do not establish actual email counts or reply links. The orchestrator inspected 50 samples on 2026-10-03 and found seven suspected cross-entity cluster merges requiring further context review. CEREC remains inspection-only with training prohibited pending rights, identity/global-index integration and annotation-quality review. See `auxiliary_source_audits.md`.

### BC3

UBC’s current download page states that the corpus is free, is licensed CC BY-SA 3.0, and requires users to submit personal/affiliation fields before the corpus is issued. It does not expose a direct corpus URL before the form. No form submission was made. UBC’s released annotation framework has an MIT license; that software license must not be mistaken for the corpus license. [BC3 corpus download page](https://www.cs.ubc.ca/labs/lci/bc3/download.html) · [Framework page](https://www.cs.ubc.ca/labs/lci/bc3/framework.html)

Published research describes 40 W3C email threads, 3,222 sentences, speech acts, and summaries; use BC3 as a small thread-aware auxiliary/evaluation set with its original annotations intact. Register `origin_corpus=W3C`, `overlap_family=W3C`. Obtain a local copy only through the form and keep any raw content outside Git. [ACL Anthology research paper](https://aclanthology.org/D10-1.pdf)

### CSpace

The original CMU paper describes about 15,000 simulated-management-course messages from working groups that signed agreements allowing certain portions to be accessible to researchers; the authors labeled 1,716 messages for their experiments and describe act categories such as Request, Deliver, Propose, Commit, Amend, Meeting and deliveredData. [CMU author paper](https://www.cs.cmu.edu/~vitor/publications/papers/carvalho06hltacts.pdf)

No legitimate public corpus download or license was found. A separate CMU author paper expressly says that privacy prevents distributing CSpace. Therefore, current disposition is **acquisition pending / no public authorized release found**. Do not reconstruct or scrape the messages from papers, code, or copied files. Any future access requires a written route approved by the dataset owner/institution. Preserve the original verb/noun pairs if authorized access is later granted; do not flatten them into FYP classes.

### Avocado / LDC2015T03

The official LDC catalog currently lists LDC2015T03 as a Web Download product, but its “View Fees” control says “Login for the applicable fee.” The public catalog therefore does not reveal an exact current corpus price. The page requires both the Organizational License Agreement and End User Agreement. The organization agreement requires two organization-level signatures (authorized officer and responsible user); every user must sign the end-user agreement. [Current LDC product page](https://catalog.ldc.upenn.edu/LDC2015T03) · [Organizational agreement](https://catalog.ldc.upenn.edu/license/Avocado%20Collection%20-%20Organization%20Agreement.pdf) · [Individual agreement](https://catalog.ldc.upenn.edu/license/Avocado%20Collection%20-%20Individual%20Agreement.pdf)

The terms limit use to linguistic research/technology development, prohibit redistribution and public reproduction of any portion, restrict server access to authorized people within the organization who signed, require organization-approved handling/training for possible PII, and impose the pseudonym “Avocado” in public/private discussion. The exact agreement wording controls; a private local copy, model-derived material, or examples should not be published without checking the agreement. The data documentation describes 279 processed custodians, PST-derived email/calendar/contact data, XML metadata and per-custodian text ZIPs; it reports 938,035 email items and 614,461 non-duplicate emails in text. [LDC README v1.0.3](https://catalog.ldc.upenn.edu/docs/LDC2015T03/README.txt)

The public LDC catalog page does not identify Bahria University as a member. Searches of public official LDC and Bahria pages found no evidence that Bahria currently has LDC membership; this is **unknown**, not evidence that it does not. Current 2026 LDC pages distinguish not-for-profit university membership and note that extra charges may apply to specified datasets; they do not expose a public Avocado price. [2026 not-for-profit membership information](https://catalog.ldc.upenn.edu/LDC2026MNP) · [LDC memberships](https://catalog.ldc.upenn.edu/memberships)

The immediate blocker is institutional: confirm any Bahria membership/account, identify the authorized institutional signatory and responsible custodian, check the LDC account-specific Avocado fee, and obtain supervisor/university approval for the data agreement and PII handling. The unsent request draft is in [`avocado_access_request.md`](avocado_access_request.md).
